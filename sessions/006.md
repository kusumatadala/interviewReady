# Session 006 — Docker — image to HTTP endpoint

**40 minutes · Core foundations · No assigned calendar date**

**Goal:** Produce a runnable container for an original Spring Boot REST app.  
**Prerequisite:** Session 005 or a documented equivalent skill.  
**Sources:** [Docker Get Started](https://docs.docker.com/get-started/) · [Dockerfile best practices](https://docs.docker.com/build/building/best-practices/)

## 1. Recall / learn — 5 minutes
- [ ] Differentiate Docker image, running container and mapped port.
- [ ] Explain build layers and why secrets should never be baked into images.

## 2. Hands-on practice — 25 minutes
- [ ] Reuse your original Spring Boot app or create `GET /healthz` returning `{"status":"ok"}`.
- [ ] Build an executable JAR; write a simple Dockerfile using `eclipse-temurin:17-jre`, `WORKDIR /app`, `COPY target/*.jar app.jar`, and Java ENTRYPOINT.
- [ ] Run `docker build -t interviewready-api .` then `docker run --rm -p 8080:8080 interviewready-api`.
- [ ] Run `curl -i http://localhost:8080/healthz`; capture HTTP status and troubleshoot if missing.

## 3. Verify / explain — 10 minutes
- [ ] Explain `EXPOSE` vs `-p`, runtime env vars, container logs, and a non-root execution improvement.
- [ ] If Docker cannot run, document the exact error and keep runtime test status blocked; don't claim a successful deployment.

**Definition of done:** Actual HTTP 200 from local container plus troubleshooting notes, or a verifiable blocker and next fix.

**Expected evidence:** `Dockerfile`, build/run commands and smoke-test output
