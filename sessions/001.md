# Session 001 — Java 17 collections and HashMap internals

**40 minutes · Core foundations · No assigned calendar date**

**Goal:** Understand key identity, hashing, collision behavior and create a reliable frequency counter.  
**Prerequisite:** None; begin here.  
**Sources:** [Java 17 HashMap API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html) · [Object.hashCode/equals](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Object.html)

## 1. Recall / learn — 5 minutes
- [ ] Describe why `equals()` and `hashCode()` must agree.
- [ ] Predict what happens if a mutable object is changed after being inserted as a HashMap key.

## 2. Hands-on practice — 25 minutes
- [ ] Write `wordCounts(List<String> words)` using `Map<String,Integer>`, with `merge` or `getOrDefault`. Define normalization assumptions.
- [ ] Create a `record Key(String tenant, int item)` and show equal records resolve the same map entry.
- [ ] Make a deliberately poor `Key` with identical hashes but distinct equality; confirm values are still retrievable (performance can degrade).
- [ ] Add tests: empty list, duplicate words, distinct case, collision keys and null-handling decision.

## 3. Verify / explain — 10 minutes
- [ ] Run tests; contrast `HashMap` and `ConcurrentHashMap` under concurrent updates.
- [ ] Explain average versus worst-case lookup, rehashing, load factor and mutable-key risk in two minutes.

**Definition of done:** Frequency counter passes at least four tests; you can explain hashing, collision handling and why overriding only `equals` is incorrect.

**Expected evidence:** `WordCounts.java` and `WordCountsTest.java` (original exercise)

### Mock interview check
**Question:** Why does changing an object after using it as a HashMap key sometimes make the entry seem to disappear?

**Answer should cover:**
- [ ] Hash bucket decided from original hash
- [ ] Mutable fields can change hash/equals
- [ ] Equals/hashCode contract
- [ ] Immutable keys are safer
- [ ] Reinsertion/rehashing nuance
