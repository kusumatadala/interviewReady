# Session 003 — Spring Boot REST and validation

**40 minutes · Core foundations · No assigned calendar date**

**Goal:** Create a small, testable REST endpoint with useful client errors.  
**Prerequisite:** Session 002 or a documented equivalent skill.  
**Sources:** [Spring MVC annotated controllers](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller.html) · [Validation](https://docs.spring.io/spring-framework/reference/core/validation/beanvalidation.html)

## 1. Recall / learn — 5 minutes
- [ ] Explain 400 versus 404 versus 409 and 201 Created.
- [ ] Describe DTO validation at the HTTP boundary versus domain invariants in services.

## 2. Hands-on practice — 25 minutes
- [ ] Create synthetic `POST /orders` taking `productId`, `quantity`; reject blank product ID and quantity ≤ 0.
- [ ] Use Java 17 DTO/record with Bean Validation and `@Valid`; return a generated order ID and HTTP 201.
- [ ] Add `@RestControllerAdvice` for a predictable JSON error shape (code, message, fieldErrors).
- [ ] Write MockMvc tests for valid 201, invalid 400, missing field and validation response shape.

## 3. Verify / explain — 10 minutes
- [ ] Run focused MockMvc tests and save results; if no app is available, create minimal sample and mark runtime tests blocked.
- [ ] Explain why exceptions from business logic should not leak stack traces or internal SQL details to callers.

**Definition of done:** At least three HTTP tests pass or a real blocker is documented; client sees a consistent safe error contract.

**Expected evidence:** `OrderController`, request DTO, exception handler and MockMvc tests (original code)
