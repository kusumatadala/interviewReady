# Session 005 — Kafka — topics, keys and consumer groups

**40 minutes · Core foundations · No assigned calendar date**

**Goal:** Explain throughput, ordering and ownership of partitions with a concrete scenario.  
**Prerequisite:** Session 004 or a documented equivalent skill.  
**Sources:** [Apache Kafka documentation](https://kafka.apache.org/documentation/) · [Spring Kafka](https://docs.spring.io/spring-kafka/reference/)

## 1. Recall / learn — 5 minutes
- [ ] Explain partition ordering versus topic-wide ordering.
- [ ] State why consumers within one group normally divide partitions.

## 2. Hands-on practice — 25 minutes
- [ ] Draw a topic with four partitions, two consumers in group A and another group B.
- [ ] Emit or sketch six synthetic case events with keys `case-A`, `case-B`, `case-C`; show how same-key events should map consistently to a partition under a stable partitioner.
- [ ] Add two consumers to group A (four total); describe which consumers might be idle and how reassignment changes on failure.
- [ ] Discuss choosing `caseId` as key versus random keys for ordering and hot-partition risk.

## 3. Verify / explain — 10 minutes
- [ ] Create a 4-row table for 1, 2, 4, 6 group consumers and the max active consumers for four partitions.
- [ ] Explain consumer lag, rebalancing and the difference between ordering and exactly-once external DB effects.

**Definition of done:** Partition/consumer diagram plus correct scaling table and 90-second explanation.

**Expected evidence:** `kafka-partition-lab.md` or original runnable Kafka demo

### Mock interview check

**Answer should cover:**

- [ ] Max active consumers
- [ ] Idle consumers
- [ ] Ordering by key
- [ ] Rebalance cost
